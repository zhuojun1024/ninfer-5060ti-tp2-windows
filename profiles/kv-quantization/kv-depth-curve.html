1. Operator level (L0 oracle): quantization error is independent of KV length

The same K/V is stored into the paged KV in the target format and in bf16, and the outputs are compared with ideal FP64 attention. rel_rmse is the RMS relative to the reference output; rmse is the absolute error.

How to read this: The relative error (top) is almost a horizontal line from length 6 → 16,384, showing that "the more tokens are stored in the KV, the relative distortion of a single attention does not grow". The absolute error (bottom) falls as 1/√N with length — because the magnitude of the softmax output itself also shrinks as 1/√N (more terms take part in the average).

Why do the nvfp4 and k8v4 curves coincide? It is not a missing measurement — the largest difference between the two on this fixture is only 3.2e-5 (0.03% relative), and on a plot with a 0.09 range they overlap completely. The reason lies in the storage format itself: k8v4 = K in FP8-row256 + V in NVFP4-G16, nvfp4 = K in NVFP4 + V in NVFP4-G16, i.e. the two have exactly the same V codec, and only K differs. But the K/V of this fixture is uniform random numbers ⇒ the attention logits are tiny and softmax is nearly uniform ⇒ the output approximates the mean of V ⇒ the error is dominated by V, and the K codec barely matters. Real long-context logits are sharper and the influence of K would be larger, so this plot is a lower bound taken from the "most favorable regime".

3. Relative PPL gap versus depth — the key plot

The cumulative PPL of each arm divided by the cumulative PPL of the reference arm. If KV quantization "amplified" under long context, this line should keep rising with depth; if quantization only brings a fixed cost, this line is horizontal. The left plot uses bf16 as the reference (1–131,071), the right plot uses fp8 as the reference (1–257,438, because bf16 cannot reach 262K).

4. Cumulative ΔNLL versus depth

Subtracted token by token from the reference arm and then cumulatively averaged (absolute, not a percentage). If the quantization error grew with context, these curves should slope up to the right.

Per-token NLL is written to token_nll.<stream>.tsv (target_index nll); target_index = t means the token is predicted from tokens[0,t), and its history depth is exactly t.

Context-independence check (whether the bf16 reference arm is usable): fp8 at --context 131072 (window 0, i.e. full history) and at --context 262144 each run once on the same stream; depth 1–131,008 are bit-identical; only the last 63 depths (131,009–131,071, i.e. the last incomplete KV page of the 131,072 window) differ, with a maximum single-token difference of 0.456, whose effect on the mean NLL over 1–131,071 is 4.7e-6, and whose effect on the mean of the last depth bucket is 2.1e-5, far smaller than the 1e-3–3e-3 order signal this report needs to resolve. Therefore the depths 1–131,071 measured by bf16@131072 can be used directly as the reference arm for the 262144 run.
