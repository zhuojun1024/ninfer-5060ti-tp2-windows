KV Quantization: Long-Context Retrieval Accuracy versus Visible Context Length

Model Qwen3.8-27B-Coder390-EfficientThink-W4A4-W8A8-Vision · TP-2 (--devices 0,1) · greedy decoding · each (arm, corpus) is an 11-point strict prefix chain, and the whole chain pays for a single longest prefill
Design: request body = [needle memo] + haystack[0:K] + [question]. K increases from 16,384 to about 262,000, and each request is a strict prefix extension of the previous one, so ninfer-serve prefix reuse merges the 11 prefills into a single longest prefill (measured: exact resend 0.9s vs cold start 127.6s, i.e. 139×; the server log also reports cache 228,352 (91.4%)). All needles are pinned at the very front of the document, so "the distance from the needle to the question" is exactly K — this is the hardest and most sensitive 0% depth setting in the stock NIAH grid.

Why this is an order of magnitude cheaper than a per-depth grid: in a depth grid every sample places the needle at a different position ⇒ the haystack token sequence is different ⇒ there is no prefix reuse at all, and each of the 88 samples pays a full 128K/260K prefill (about 5.5 hours). The prefix chain pushes the cost down to a single longest prefill (about 25 minutes), at the price of losing the "depth" dimension.

Note: the needle and the question are both English; the Chinese document only swaps the haystack — consistent with what the stock NIAH adapter does.
